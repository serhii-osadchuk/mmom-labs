Документ складено так, щоб викладач бачив **окремо** три речі:

**C** — що змінено для варіанта 17. Повний перелік рядків: [`results/changes.diff`](results/changes.diff).

## A. Артефакти копіювання з PDF (без цього код не запускається)

Прототип перенесено в [`original/pn_abm_original.py`](original/pn_abm_original.py) без змін логіки.
При копіюванні тексту з PDF виникають такі помилки. Кожну перевірено компіляцією:

| № | Артефакт | Де | Наслідок | Виправлення |
|---|---|---|---|---|
| A1 | Довгий рядок-розділювач `# ====…` розривається на два: другий рядок `====` без `#` | заголовки розділів 1–3 | `SyntaxError: invalid syntax` | з'єднати в один рядок коментаря |
| A2 | Коментар `# Стани агента: …, 'IN_CZ', 'AT_MACHINE'` розривається, і `'AT_MACHINE'` опиняється на початку рядка | `AMRAgent.__init__` | `IndentationError` | з'єднати в один рядок коментаря |
| A3 | Подвійна двокрапка `elif transition_id == 't_exit_CZ_AMR1': :` у текстовому шарі PDF | `PetriNetSupervisor.can_trigger` | `SyntaxError: invalid syntax` | видалити зайву `:` |
| A4 | Відступи в текстовому шарі PDF стискаються до 1 пробіла | весь файл | можливі `IndentationError` при змішуванні | відновити відступи по 4 пробіли за малюнком у PDF |
| A5 | Довгий пояснювальний коментар у `update_motion` | `AMRAgent.update_motion` | логіку не ламає | скорочено (лише коментар) |

Після виправлень A1–A4 оригінал працює: спрацьовують 4 переходи, кінцеве маркування
`[1, 0, 0, 0, 0, 1, 1]` збігається з малюнком у PDF (див. `results/original_final_frame.png`,
запуск: `python run_original_headless.py`).

## B. Обмеження прототипу, виявлені під час аналізу (в оригіналі не виправлялись)

| № | Спостереження | Наслідок |
|---|---|---|
| B1 | Код жорстко розрахований на 2 AMR і 2 верстати: вектор `M` з 7 елементів і чотири гілки `if/elif` | для 3 AMR і 3 верстатів потрібне узагальнення |

| B5 | Схематичне креслення: сіра «стіна» накладається на коридор AMR_1 (y = 6), підписи «Верстат M1/M2» не вміщуються в прямокутник | лише візуальні недоліки |

## C. Зміни для варіанта 17 (файл [`pn_abm_variant17.py`](pn_abm_variant17.py))

Дані варіанта: **3 AMR, 3 верстати, 2-місний паралельний проїзд (K = 2), v_max = 1,1 м/с,
межі критичної зони [6,0; 15,0] м, час обробки 8,0 с.**

| Клас / функція | Було (прототип) | Стало (варіант 17) | Причина |
|---|---|---|---|
| Константи (нова секція «0») | значення вбудовані в код | `N_AMR=3`, `N_MACHINES=3`, `CZ_CAPACITY=2`, `V_MAX=1.1`, `CZ_ENTRY_X=6.0`, `CZ_EXIT_X=15.0`, `T_PROC=8.0` | умова варіанта; для іншого варіанта змінюються лише вони |
| `PetriNetSupervisor.__init__` | `M = [1,1,1,0,0,0,0]` | вектор довжини `1 + 4n`; `M[0] = K`; додано позиції `p_Mk_done`; додано `now` та `log` | узагальнення на n роботів, K = 2 (B1, B2) |
| `PetriNetSupervisor.i_free/i_in_cz/i_work/i_done`, `parse` | — (нових методів не було) | допоміжні методи індексів та розбору імені переходу `t_enter_CZ_AMRk` | замість чотирьох жорстких гілок |
| `can_trigger`, перехід входу | `self.M[0] == 1 and self.M[1] == 1` | `self.M[0] >= 1 and self.M[i_free(k)] == 1` | у проході K = 2 місця: умова «є хоча б одне вільне» |
| `can_trigger`, `trigger` | 4 переходи (`enter`/`exit` для AMR1, AMR2) | `enter_CZ`, `exit_CZ` для будь-якого k + новий `finish` (`t_finish_Mk`) | B1, B3 |
| `trigger` | — | запис у `log` (час, перехід, маркування) | таблиця переходів для звіту та перевірка інваріантів |
| `AMRAgent.__init__` | `v_max = 1.2` (константа) | параметри `v_max=V_MAX`, `t_proc=T_PROC`; нові поля `proc_timer`, `wait_time` | швидкість і час обробки з варіанта |

| `run_production_simulation`, геометрія | `cz_entry_x = 8.0`, `cz_exit_x = 16.0`; 2 верстати; 2 роботи | межі `[6; 15]`; верстати M1–M3 з `y = 6, 4, 2`; AMR1–AMR3 стартують з `x = 1,0; 0,5; 0,0` | 3 AMR, 3 верстати |
| `run_production_simulation`, цикл | `steps = 220` (22 с) | `steps = T_END/DT = 450` (45 с) | довше виконання через очікування та обробку 8 с |

| `run_production_simulation`, виведення | `plt.show()` | додатково повертає `supervisor, amrs`; збереження кадрів `SNAPSHOT_*` | автотест і кадри для звіту |
